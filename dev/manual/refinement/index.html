Graph refinement

refine is an algorithm that applies lifts: it solves a certificate, reads where it is tight, applies a lift there, and solves again. A lift never makes the certificate worse, so the bound can only improve. Refinement: splitting nodes at tight edges runs it.

Refinement is a stability tool: each algorithm below comes from a paper on the joint spectral radius, the bound is an upper bound on it, and it can be proved exact. It also runs on safety, where the margin never decreases but no run is ever certified optimal; see Other problems.

The loop

A path-complete graph with a quadratic function at each node gives an upper bound $γ^*(G)$ on the joint spectral radius, the optimum of $\min γ$ subject to $γ^2 P_a \succeq A_i^\top P_b A_i$ on every edge $(a, b, i)$ and $P_a \succ 0$; jsr_bound bisects on $γ$. A lifted graph gives a bound at least as good, with a larger program. de_bruijn adds nodes everywhere, remembering the last k modes at mᵏ nodes; refine adds them where the solution is tight. At each step:

  1. Solve. jsr_bound returns a certificate: the rate and one function per node.
  2. Find the tight edges. An edge is tight when its inequality is active. edge_slacks measures them, tight_edges names them, tight_subgraph keeps only them ((Ninite and Jungers, 2026), Def. 4).
  3. Lift. next_graph of the algorithm reads the certificate and returns the next graph, a lift of the current one.
  4. Repeat on the lifted graph.

The algorithms

AlgorithmAt each stepStarts fromSource
TightNodeSplitting, the defaultthe forward lift of the node with the most tight outgoing edges, at least twothe dual of de_bruijn(1, M)(Ninite and Jungers, 2026), Algorithm 1
BestTightEdgeLiftingthe four splits and products at every tight edge, each solved, the lowest objective keptthe one-node graph(Athanasopoulos and Jungers, 2019), Example 2
Hierarchy(lift)lift applied to the whole graphthe one-node graph(Philippe et al., 2016); (Jongeneel and Jungers, 2025), §IV-A

TightNodeSplitting follows Algorithm 1 of (Ninite and Jungers, 2026). Its step is the forward lift at a node, one copy per successor, so a node whose only successor is itself cannot be split: on the one-node graph the lift changes nothing. The algorithm passes such nodes over and starts, as the paper's experiments do, from the dual De Bruijn graph of order 1. Ties go to the node with the fewest outgoing edges, then the lowest index, so a run is deterministic; rng breaks them at random instead.

BestTightEdgeLifting follows Example 2 of (Athanasopoulos and Jungers, 2019): every candidate is solved, one solve each at every step, and the best is kept. The products write words on the edges, which only stability accepts, so they are left out on other problems.

Hierarchy lifts the whole graph at every step. Hierarchy(PathDependentLift(1)) from the one-node graph goes up the De Bruijn hierarchy one order per step, so the de_bruijn graphs are a special case of the loop. Hierarchy(CompositionLift(1)) applies the composition lift, which can strictly improve a graph for templates closed under composition ((Jongeneel and Jungers, 2025), Ex. IV.4); it throws where the lift is not valid.

A new algorithm is a subtype of AbstractRefinementAlgorithm that implements next_graph, and initial_graph when it starts elsewhere than the one-node graph.

Where it starts

refine(template, problem) starts from initial_graph of the algorithm. refine(template, graph, problem) starts from a graph of yours. Path-completeness is checked on that first graph only; every lift preserves it.

When it stops

status on the returned RefinementTrace says which of five things happened.

OPTIMALthe rate is the joint spectral radius
STALLEDstall_max steps in a row did not improve the objective by rtol
DEPTH_REACHEDdepth_max reached with the bound still falling
STOPPEDthe stop predicate returned true, for example c -> c.rate < 1
EXHAUSTEDthe algorithm had no next graph, and the gap had not closed

Only OPTIMAL proves the rate equal to the joint spectral radius. The trace keeps every certificate and every Lifted step, so a run can be read back: rates, graphs, steps and the origins of each node.

Two certificates of optimality

The rate is an upper bound on the joint spectral radius. Two independent tests, run at every step, can prove it equal.

Structural. If every node has at most one outgoing edge in the tight subgraph, then $γ^*(G) = ρ(\mathcal{A})$ ((Ninite and Jungers, 2026), Thm. 4). is_jsr_exact tests this condition. It is sufficient, not necessary, so false means unknown, and its answer depends on the tightness tolerance.

Numerical. A cycle $(a_1,a_2,i_1) \dots (a_k,a_1,i_k)$ of the tight subgraph forces $γ \ge ρ(A_{i_k} \cdots A_{i_1})^{1/k}$, and any product of modes bounds the joint spectral radius from below. jsr_lower_bound returns the largest such bound over the cycles of the tight subgraph. The interval between it and the rate contains the joint spectral radius whatever the tolerance, since a cycle of the tight subgraph is a cycle of the graph.

The two tests apply in different cases. For two opposite rotations scaled by 0.9, $P = I$ is optimal on any graph and every edge is tight, so Theorem 4 never applies and the loop would split indefinitely at a constant bound; the lower bound equals the rate at the first step.

The tolerances

rtolbisection tolerance of each jsr_bound call
atolhow close to zero counts as tight
gap_tolthe gap between the rate and the lower bound at which the run stops

Bisection stops above the optimum, so the slack of an active edge is of the order of the bisection gap, not zero. With atol too small the tight subgraph is empty and the loop learns nothing: there is no node to split, no cycle to bound the rate from below, and is_jsr_exact answers false, since at the optimum the tight subgraph contains a cycle ((Ninite and Jungers, 2026), Prop. 1). refine therefore requires atol ≥ 10 rtol. Every function reading tight edges shares the default atol = 1e-4; read a certificate from jsr_bound with an atol at least ten times the rtol it was computed to.

Other problems

refine runs on every problem that implements best_certificate, objective, edge_slacks and optimality_gap; stability and safety do. On safety each node of a lifted graph can keep the barrier of the node it came from, so the margin, read as c.margin on each certificate of the trace, never decreases. Safety has no lower bound, so its runs end on a stall, the depth budget or an exhausted algorithm, never on OPTIMAL. What works with what says which templates the loop runs on.

PathCompleteCertificates.refine — Function
refine(template, problem; optimizer, kwargs...)
refine(template, graph, problem; optimizer, algorithm = TightNodeSplitting(),
       stop = Returns(false), depth_max = 5, stall_max = 1, atol = 1e-4,
       gap_tol = 1e-6, rtol = 1e-6, path_complete = true, kwargs...)

Refine graph, by default initial_graph(algorithm, system), until the optimality_gap of its certificate closes; returns a RefinementTrace. At each step next_graph of algorithm gives the next graph, a lift of the current one.

  • The run stops when stop(certificate) holds, the gap is at most gap_tol, stall_max steps in a row fail to improve the objective by rtol, depth_max graphs are visited, or no candidate is left.
  • rtol is the solve tolerance and atol decides tightness, with atol ≥ 10 rtol.
  • path_complete = false skips the path-completeness check of the starting graph.

Other keywords go to best_certificate.
