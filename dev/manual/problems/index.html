Problems

A problem says what the edge inequality is. The graph, the templates and the aggregation are the same across all three.

ProblemEdge inequality on $(s, d, i)$Entry points
StabilityProblem$V_d(A_i x) \le \gamma^{d}\, V_s(x)$certify, is_stable, jsr_bound
SafetyProblem$B_d(A_i x) \le B_s(x)$, plus set separationcertify
OptimalControlProblem$x^\top Q x + u^\top R u + V_d(A_i x + B_i u) \le V_s(x)$certify

Stability

(Ahmadi et al., 2014). certify solves once at a given rate; is_stable asks only whether that rate is feasible, and jsr_bound bisects for the best one. Every template works here. The exponent $d$ is the template's rate_exponent, so $\gamma$ means the same contraction per step whichever template is in use, and an edge reading a word of $k$ modes scales as $\gamma^{dk}$.

PathCompleteCertificates.jsr_bound — Function
jsr_bound(template, graph, problem; optimizer, rtol = 1e-3,
          max_iterations = 100, initial_upper = 1.0)

Estimate an upper bound on the joint spectral radius by bisection.

At each candidate gamma, solve the fixed-gamma feasibility problem over every edge (a, b, i).

Returns a StabilityCertificate. Its rate is the smallest feasible bound found to relative tolerance rtol; functions(certificate) are the node Lyapunov functions, and certificate(x) evaluates the common one.

Estimate a joint-spectral-radius bound for an input-free switched system.

Safety

(Anand et al., 2024). A barrier is negative on the initial set, positive on the unsafe set, and never increases along a transition, so the region it cuts out is invariant, contains the initial set, and never reaches the unsafe one.

SafetyProblem takes both sets in homogeneous coordinates, as $\{x : [x; 1]^\top S [x; 1] \ge 0\}$.

What `margin` is

The edge inequality is non-strict. It must be, since a strict one collapses around any cycle, and every path-complete graph has one. The strictness sits on the set separation instead, and certificate.margin is how much of it the solver achieved.

Optimal control

(Ninite et al., 2026), for a switched system with an input: the mode is adversarial, the input is yours. Returns the bound and a state-feedback gain per node.

PathCompleteCertificates.certify — Function
certify(template, graph, problem; optimizer, kwargs...)

Solve for the guarantee, and return an AbstractCertificate.

One entry point for every problem: build the model, solve it, and read the result back. What each problem certifies is a typed field on the certificate it returns — rate, margin, gains.

Check is_feasible before reading anything else. An infeasible result is still a certificate object, carrying the solver status so that "no certificate exists in this template on this graph" is distinguishable from "the solver gave up".

Not to be confused with refutation, when that lands: sampling for a violation is a cheap way to learn you are wrong, and finding none proves nothing.

source

Convex only after the substitution $S = P^{-1}$, $Y = KS$, which is specific to the quadratic case, so this problem is tied to QuadraticTemplate. It also needs a complete graph, not merely a path-complete one.

`objective` is not the bound

It is a volume heuristic for choosing among feasible certificates, and is routinely negative. The bound is certificate(x).

Reading a certificate

is_feasible(c)was anything certified at all?
status(c)the solver's termination status, when it was not
functions(c)the fitted node functions, one per node, each callable
c(x)the common function, what graph and template certify together

What each problem specifically certifies is a field of its own: StabilityCertificate.rate, SafetyCertificate.margin, OptimalControlCertificate.gains.

Check `is_feasible` first

An infeasible result is still a certificate object. It carries the solver status, so you can tell "no certificate exists here" from "the solver gave up".

Reading a stability certificate further

A stability certificate says more than its rate, and the graph layer is built on what it says.

edge_slackshow far each edge inequality is from being active
tight_edges, tight_subgraphthe edges that hold the bound up ((Ninite and Jungers, 2026), Def. 4)
is_jsr_exactthe rate is the joint spectral radius when every node has at most one tight outgoing edge ((Ninite and Jungers, 2026), Thm. 4)
jsr_lower_boundthe bound from below that the cycles of the tight subgraph give, bracketing the rate
dual(certificate)the same certificate on the dual graph, for the transposed system, in the dual template ((Debauche, 2024), Lemma 6.25); see Duality

Tightness is read against a tolerance, because a bisected solution never reaches an exact zero; Refinement: designing the graph explains how to set it.

What a refinement loop reads

refine is generic in the problem. A problem joins it by answering three questions: best_certificate, the solve that drives one step; objective, the number to improve; and optimality_gap, how far that number is known to be from the best any graph could do. Stability answers all three with jsr_bound, the rate and the bracket above. Safety and optimal control do not answer them yet, so today the loop runs for stability.
