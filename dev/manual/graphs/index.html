Path-complete graphs

A certificate graph is a directed graph with a mode on every edge: nodes 1:n, and an edge (s, d, i) reading "from node s, mode i leads to node d". It is a GraphAutomaton of HybridSystems.jl, the type the automaton of a constrained system has too. Build one with empty_graph and add_edge!, and read it with nodes, edges, source, dest, label, outgoing_edges, incoming_edges and alphabet.

Path-completeness

A graph is path-complete for a language when every sequence of the language can be read as a path in it ((Ahmadi et al., 2014), Def. 2.2). The edge inequalities of a certificate are local, and what they certify is the property over the language the graph reads: a path-complete graph reads every admissible sequence, so the certificate holds for the whole system, while a graph that is not reads a smaller language and certifies the property for that language only. Every problem checks the graph against the system's language before solving.

PathCompleteCertificates.is_path_complete — Function
is_path_complete(graph)
is_path_complete(graph, alphabet)
is_path_complete(graph, automaton)

Whether every switching sequence of the language is readable in graph — Definition II.1 of Philippe, Athanasopoulos, Angeli & Jungers: for any $k ≥ 1$ and any $σ_1 … σ_k$ over the alphabet there is a path $(s_i, s_{i+1}, σ_i)_{i=1..k}$ in the graph.

This is what makes a certificate speak for the whole system: the edge inequalities certify the property over the language the graph reads, which is every admissible sequence exactly when the graph is path-complete.

It is not graph-theoretic completeness, where every pair of vertices is adjacent, and it is strictly weaker than is_complete — see that docstring.

Decided by the subset construction: a word is readable from some node exactly when the set of nodes reachable by it is nonempty, so the graph is path-complete iff the subset construction started from all nodes never reaches the empty set. That is a finite search, since there are finitely many subsets.

The second argument says which switching sequences must be readable. Under arbitrary switching it is the alphabet, and every sequence of modes over it must be; under constrained switching it is the system's automaton, and every path of the automaton must be, which the same construction decides in product with it. Pass language of the system whenever the question is about a certificate: without a second argument the alphabet is the modes graph happens to use, so a graph that never mentions a mode passes for its own labels and is not path-complete for a system that has that mode.

A WordGraph is path-complete when its expanded_form is: every word of the language is then a factor of the label of some path.

source

Deciding it is the subset construction of automata theory: exponential in the number of nodes in the worst case, cheap on the graphs met in practice, and skipped altogether on a complete or co-complete graph. The check runs once per solve, and path_complete = false on an entry point waives it for a graph whose construction guarantees the property, such as a refinement of a path-complete graph. Waived wrongly, the result certifies nothing, with no error.

Ask about the system's language

is_path_complete(graph) alone asks about the modes the graph happens to use, so a graph that never mentions a mode passes trivially. Ask is_path_complete(graph, language(system)), or let the problems do it.

Complete, co-complete, and the common function

Two stronger properties ((Philippe et al., 2017), Def. III.2): a graph is complete when every node has an outgoing edge for every mode, and co-complete when every node has an incoming edge for every mode. Both imply path-completeness; neither is necessary. What they decide is the form of the common function, the single function the node functions $V_s$ of a certificate combine into: the minimum over the nodes on a complete graph, the maximum on a co-complete one (Cor. III.3), and a minimum of maxima over the observer graph otherwise (Thm. III.8). common picks the right one, and certificate(x) evaluates it.

PredicateMeaning
is_path_completeevery admissible sequence is readable as a path
is_completeevery node has an outgoing edge for every mode
is_co_completeevery node has an incoming edge for every mode
PathCompleteCertificates.common — Function
common(template, graph, problem, Ps, x)

Evaluate at x the common function the node functions Ps of a certificate on graph combine into (Philippe, Athanasopoulos, Angeli & Jungers): the minimum over the nodes on a complete graph (Cor. III.3), the maximum on a co-complete one, and a minimum of maxima over the observer construction otherwise (Thm. III.8). Depending on problem it is a common Lyapunov function, a common barrier function, or an upper bound on the value function.

The De Bruijn graphs

de_bruijn(k, M) is the primal De Bruijn graph of order k on M modes ((Debauche, 2024), Def. 6.10): one node per word of k modes, the last k modes read, and from every node an edge per mode to the node that remembers it; Mᵏ nodes, and complete. Its dual is the dual De Bruijn graph, co-complete. The two hierarchies are the classical path-complete graphs ((Ahmadi et al., 2014)); going one order up is the backward split at every edge, so the certified bound never gets worse ((Philippe et al., 2016)), at the price of M times as many nodes.

common_graph(system) is order zero: the common Lyapunov function graph $G_0$ under arbitrary switching, the automaton itself under constrained switching.

PathCompleteCertificates.de_bruijn — Function
de_bruijn(order, n_modes)

The primal De Bruijn graph of order order on n_modes modes: a node per tuple of order modes, the last ones read, newest first, and from (i₁, …, iₗ) an edge reading σ to (σ, i₁, …, iₗ₋₁) (Ninite & Jungers, Def. 6; Debauche, Def. 6.10, which writes the tuple oldest first). It is complete, with n_modes^order nodes, and path-complete. The dual De Bruijn graph, co-complete, is dual(de_bruijn(order, n_modes)).

source
PathCompleteCertificates.common_graph — Function
common_graph(system)

The common Lyapunov function graph $G_0$ of the system (Debauche, Della Rossa & Jungers, Prop. 2): one node with a loop per mode, on which a certificate is a single common function, and which every path-complete graph is no worse than. Under constrained switching its counterpart is the system's own automaton, one function per state (Philippe, Essick, Dullerud & Jungers), and that is what is returned.

Either reads the system's language by construction, and every refinement preserves that, so refine starts here and never re-decides path-completeness.

source

Refinement grows a graph where its certificate is tight rather than everywhere; see Graph improvement via refinements.

Words on edges

An edge may read a word, a sequence of modes, in a WordGraph: one inequality on the product $A_{i_k} \cdots A_{i_1}$ and nothing on the states in between. The expanded_form reads the same language with one mode per edge and a fresh node per intermediate step ((Ahmadi et al., 2014), Def. 2.1), and a word graph is path-complete exactly when its expanded form is. Words are sound for stability only, where an inequality on a product still bounds the joint spectral radius; safety and optimal control need every state along the way, and throw on a word graph. The product refinements write words.

The dual graph

dual(graph) reverses every edge and every word ((Debauche, 2024), Def. 6.3), and the result is path-complete exactly when the graph is (Prop. 6.6). Duality is the full account.
