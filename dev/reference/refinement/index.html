Refinement reference

Neither axis, and for the same reason as common: refine reads the graph, a template and a problem at once. It is the package's one loop that designs the certificate rather than solving for one on a graph you supplied, and it names no problem: what it needs from one are the methods best_certificate, objective, edge_slacks and optimality_gap of the problem interface.

The graph operations it drives are in the Lift reference.

The loop

PathCompleteCertificates.DEPTH_EXHAUSTED — Constant
DEPTH_EXHAUSTED

depth_max certificates were solved with the search still making progress.

source
PathCompleteCertificates.EXHAUSTED — Constant
EXHAUSTED

The strategy proposed no candidate — nothing was left to lift — and the gap had not closed. With the default strategy and a letter graph this cannot happen without OPTIMAL: no node held at two tight outgoing edges is Theorem 4's hypothesis. With another strategy it is a genuine outcome, a dead end that proves nothing.

source
PathCompleteCertificates.OPTIMAL — Constant
OPTIMAL

The optimality_gap closed: the certificate is proved as good as any graph could make it, and the run stopped because it had nothing left to prove. For stability, rates(trace)[end] is then the joint spectral radius, not merely a bound on it — reached either by the cycle bracket of jsr_lower_bound, sound whatever atol was, or by is_jsr_exact, Theorem 4 of Ninite & Jungers.

source
PathCompleteCertificates.STALLED — Constant
STALLED

stall_max lifts in a row failed to improve the objective.

Worth its own outcome because a graph already attaining the exact joint spectral radius holds every edge tight, so it always looks splittable and would otherwise be grown forever at a constant bound.

source
PathCompleteCertificates.STOPPED — Constant
STOPPED

The stop predicate held on the last certificate — for stability, the rate fell below 1 when stop = c -> c.rate < 1, already a proof.

PathCompleteCertificates.refine — Method
refine(template, problem; optimizer, kwargs...)
refine(template, graph, problem; optimizer, strategy = SplitTightNode(),
       select = :first, stop = Returns(false), depth_max = 5, stall_max = 1,
       atol = 1e-4, atol_max = atol, gap_tol = 1e-6, rtol = 1e-6,
       path_complete = true, kwargs...)

Iteratively lift graph to tighten the certificate it carries, until the problem's optimality_gap closes or the search runs out.

Without a graph, the run starts from seed of the system: the one-node graph under arbitrary switching, the automaton itself under constrained switching.

Each step solves best_certificate — jsr_bound for stability — and hands the certificate to strategy, any callable (certificate; atol) -> Vector{Lifted} returning candidate graphs, best guess first. The default SplitTightNode splits the node held at the most tight outgoing edges; LiftTightEdges tries every local lift at every tight edge; Hierarchy applies one global lift. select takes the first candidate, or with :best solves every candidate and keeps the lowest objective — one solve per candidate, the rule of Athanasopoulos & Jungers.

Returns a RefinementTrace.

Stopping

  • optimality_gap≤ gap_tol → OPTIMAL. Checked every step, not only when the search runs dry: a graph can be optimal long before it is structurally exhausted, and for stability the cycle bracket does not depend on atol being right;
  • stop(certificate) → STOPPED, an explicit request taken before the gap; c -> c.rate < 1 stops a stability run at the first proof of stability;
  • stall_max lifts in a row not improving the objective by more than rtol → STALLED. Raise stall_max to cross a plateau;
  • depth_max certificates solved → DEPTH_EXHAUSTED;
  • no candidate → EXHAUSTED. With the default strategy on a letter graph this coincides with OPTIMAL, since "no node holds two tight outgoing edges" is Theorem 4's hypothesis, and the gap is tested first.

The tolerances

rtol is the solve tolerance forwarded to best_certificate — the bisection tolerance of each jsr_bound call — and atol decides tightness. atol ≥ 10 rtol is enforced: bisection stops just above the optimum, so an active edge measures about the bisection gap, not zero. On a rotation-and-shear pair over de_bruijn(1, 2) at rtol = 1e-6 the three active edges measure 1.3e-7, 6.0e-7 and 2.9e-6 against 0.17 for the slack one. Below a decade the tight subgraph can come out empty, every node then satisfies is_jsr_exact vacuously, and the run certifies a bound that is not the joint spectral radius.

atol_max is the safeguard, off by default (atol_max == atol). Set it higher and a dead end is not taken at face value: the tolerance is multiplied by ten, up to the ceiling, and the same certificate re-read. Nothing is re-solved, because the tolerance decides how a solution is read, not what it is. Its remaining purpose is a solution whose accuracy is worse than rtol suggests.

path_complete decides the seed only: a lift of a path-complete graph is path-complete, so the loop asserts rather than re-deciding a PSPACE-complete question. Other keywords go to best_certificate.

Strategies

PathCompleteCertificates.Hierarchy — Type
Hierarchy(lift)

One candidate a step: lift applied to the whole graph — a global lift, or a local one at every edge. Hierarchy(PathDependentLift(1)) from the one-node graph walks the De Bruijn hierarchy; Hierarchy(CompositionLift(1)) is the refinement of Jongeneel & Jungers.

source
PathCompleteCertificates.LiftTightEdges — Type
LiftTightEdges(lifts = (ForwardEdgeSplit(), BackwardEdgeSplit(),
                        ForwardEdgeProduct(), BackwardEdgeProduct()))

The rule of Athanasopoulos & Jungers: every local lift at every tight edge, as candidates. Meant for select = :best in refine, which solves each and keeps the best — their Example 2 reaches stability in fifteen such steps on a polyhedral template.

A split is proposed only where it changes the graph: a node with a single outgoing (incoming) edge is not split along it.

source
PathCompleteCertificates.SplitTightNode — Type
SplitTightNode(lift = ForwardEdgeSplit(); rng = nothing)

The rule of Ninite & Jungers: split the node held at the most tight outgoing edges, with lift on its out-star. One candidate, or none when no node holds two — which on a letter graph is exactly the hypothesis of is_jsr_exact, so the search drying up is itself the certificate.

Ties go to the cheapest split — fewest outgoing edges, since the split adds one node per edge and node count is the budget the comparison with de_bruijn is about — and then to the lowest-numbered node, so a run is identical on every machine and Julia version. Pass an rng to break the remaining ties at random instead; seeding one does not make a run reproducible across Julia versions, rand(rng, ::Vector) being free to sample differently between them.
