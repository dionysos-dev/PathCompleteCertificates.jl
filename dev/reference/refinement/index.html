Refinement reference

refine is an algorithm that applies lifts where a certificate is tight; see Refining the graph.

The interface

PathCompleteCertificates.AbstractRefinementAlgorithm — Type
AbstractRefinementAlgorithm

The supertype of the algorithms refine can run. A new algorithm subtypes it and implements next_graph.

source
PathCompleteCertificates.initial_graph — Method
initial_graph(algorithm, system)

The graph refine(template, problem) starts from: common_graph of system unless algorithm says otherwise.

source
PathCompleteCertificates.next_graph — Function
next_graph(algorithm, certificate; atol, solve)

The next graph after certificate, as (lifted, next), or nothing if there is none. next is the certificate on lifted if the algorithm already solved it, nothing otherwise.

Edges with slack at most atol are tight; solve(lifted) solves a candidate.

source

The algorithms

PathCompleteCertificates.TightestNodeSplitting — Type
TightestNodeSplitting(; rng = nothing)

Algorithm 1 of (Ninite and Jungers, 2026), with OutSplitLift at a node, which refines their forward lift: split the node with the most tight outgoing edges, among those with at least two, into one copy per outgoing edge. When no node has two tight outgoing edges, there is no next graph.

Several nodes can hold as many tight edges. Among them the one with the fewest outgoing edges is split, since its lift adds the fewest nodes; a tie that remains goes to the lowest index, so a run is deterministic but depends on how the nodes are numbered. With rng, for example rng = MersenneTwister(1), that last tie is drawn at random instead.

From common_graph, the first step gives the dual of de_bruijn(1, n_modes).

source
PathCompleteCertificates.BestOfTightEdgeLifts — Type
BestOfTightEdgeLifts(lifts = (OutSplitLift(), InSplitLift(),
                              ForwardProductLift(), BackwardProductLift()))

The procedure of (Athanasopoulos and Jungers, 2019; Ex. 2). At each step, every lift of lifts is applied at every tight edge, one edge at a time; by default these are its partial P*-, P-, T- and T*-lifts (Defs. 7, 6, 4 and 5). Each candidate graph is solved, and the one with the lowest rate is kept.

PathCompleteCertificates.refine — Method
refine(template, problem; optimizer, kwargs...)
refine(template, graph, problem; optimizer, algorithm = TightestNodeSplitting(),
       stop = Returns(false), depth_max = 5, stall_max = 1, atol = 1e-4,
       gap_tol = 1e-6, rtol = 1e-6, check_path_complete = true, kwargs...)

Refine graph, by default initial_graph of algorithm on the system of problem, until the optimality_gap of its certificate closes, and return a RefinementTrace. At each step next_graph of algorithm gives the next graph, a lift of the current one.

  • The run stops when stop(certificate) holds, the gap is at most gap_tol, stall_max steps in a row fail to improve the objective by rtol, depth_max graphs are visited, or no candidate is left.
  • rtol is the bisection tolerance on the rate, atol the tightness threshold on the slacks, with atol ≥ 10 rtol.
  • check_path_complete = false skips the path-completeness check of the starting graph.

Other keywords go to certify.
