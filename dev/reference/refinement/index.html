Refinement reference

A refinement transforms a path-complete graph into one that is no worse for every template; refine applies one where a certificate is tight and repeats. The loop names no problem: it reads best_certificate, objective, edge_slacks and optimality_gap, and a problem that answers them joins it. See Graph improvement via refinements for the picture. A new refinement is one file in src/refinements/catalogue/ answering refine.

The interface

PathCompleteCertificates.AbstractRefinement — Type
AbstractRefinement

A transformation of a path-complete graph into a path-complete graph that is guaranteed no worse for every template: a copy inherits its origin's function, a product chains two edge inequalities (Athanasopoulos & Jungers, Thm. 1; Ninite & Jungers, Thm. 3). Applied where a certificate is tight it is the step of refine; applied everywhere it is one of the classical hierarchies.

A refinement is an instance, applied by refine: a local one at a locus of edges, refine(refinement, graph, edges), or at every edge when none is given; a global one to the whole graph, refine(refinement, graph). Both return a Refined. A new refinement is one file answering refine.

source
PathCompleteCertificates.Refined — Type
Refined(graph, origins)

What a refinement returns: the refined graph and, for each of its nodes, the node of the original it came from. A certificate on the original, copied along origins, is one on the refined graph, which is what makes a refinement valid for every template (Debauche, Della Rossa & Jungers, Def. 6(c)). reindex reads it to carry per-node template data across, and a RefinementTrace keeps it.

source
PathCompleteCertificates.origins — Method
origins(refined)

Where each node of a Refined or a Lifted graph came from.

PathCompleteCertificates.refine — Function
refine(refinement, graph, edges) -> Refined
refine(refinement, graph) -> Refined

Apply one refinement: at a locus of edges for a local one, to the whole graph for a global one. A local refinement given no locus is applied at every edge. The iterated form, driven by a certificate, is refine(template, graph, problem).

The dual of a refinement

PathCompleteCertificates.DualRefinement — Type
DualRefinement(refinement)

The dual of a refinement, dual(R)(G) = dual(R(dual(G))) (Debauche, Def. 7.4): every backward atom is the dual of a forward one, and dual of the result is the forward one again. A locus is mapped into the dual graph and the result mapped back; a global refinement is applied to the dual graph whole, so dual(PathDependentRefinement(k)) from the one-node graph is the dual De Bruijn graph.

The catalogue

PathCompleteCertificates.ForwardEdgeSplit — Type
ForwardEdgeSplit()

Split the source of each edge of the locus: a copy of it owning that one outgoing edge and every incoming edge (Athanasopoulos & Jungers, Def. 7, the partial P*-lift). Every incoming edge of a split node enters every copy, a self-loop included; an outgoing edge leaves the copy that owns it, or the node itself when it is not in the locus; a self-loop in the locus returns from its copy to the node. A node whose outgoing edges are all in the locus is replaced by its copies, and a node left without edges is deleted. Copies are numbered last.

At one edge this is the paper's lift; a locus of several edges at one node is that lift applied edge by edge, the loop last. On outgoing_edges(graph, s), the default step of refine, it gives s one copy per outgoing edge, which is the forward lift of Ninite & Jungers (Def. 3) whenever no two edges of s share a destination; their lift gives one copy per successor instead. Its dual, BackwardEdgeSplit, splits destinations along incoming edges.

source
PathCompleteCertificates.BackwardEdgeSplit — Type
BackwardEdgeSplit()

Split the destination of each edge of the locus: a copy of it owning that one incoming edge and every outgoing edge (Athanasopoulos & Jungers, Def. 6, the partial P-lift). The dual of ForwardEdgeSplit; at every edge it is PathDependentRefinement(1).

source
PathCompleteCertificates.ForwardEdgeProduct — Type
ForwardEdgeProduct()

Replace each edge (s, d, w) of the locus by the edges (s, d′, w·u) for every edge (d, d′, u) leaving its destination (Athanasopoulos & Jungers, Def. 4, the partial T-lift). The result is a WordGraph: one inequality on a product of modes replaces one on a single step, and no node is added. At every edge this is ProductRefinement(2); its dual, BackwardEdgeProduct, folds an edge into the edges entering its source.

source
PathCompleteCertificates.BackwardEdgeProduct — Type
BackwardEdgeProduct()

Replace each edge (s, d, w) of the locus by the edges (s′, d, u·w) for every edge (s′, s, u) entering its source (Athanasopoulos & Jungers, Def. 5, the partial T*-lift). The dual of ForwardEdgeProduct.

source
PathCompleteCertificates.PathDependentRefinement — Type
PathDependentRefinement(k)

The path-dependent lift of order k (Philippe, Essick, Dullerud & Jungers, Def. 3): BackwardEdgeSplit at every edge, k times. Its nodes are the paths of length k of the original graph and its edges the paths of length k + 1. From the one-node graph it is de_bruijn(k, M), and its dual the dual De Bruijn graph; from a constraint automaton, the k-memory lift of the constrained system. origins record the last node of each path.

source
PathCompleteCertificates.ProductRefinement — Type
ProductRefinement(T)

The T-product lift (Philippe, Essick, Dullerud & Jungers, Def. 2): the same nodes, one edge per path of length T, reading the concatenated word. A WordGraph. ProductRefinement(2) is either edge product at every edge; the construction is self-dual.

source

Strategies

PathCompleteCertificates.Hierarchy — Type
Hierarchy(step)

One candidate a step: step applied to the whole graph — a global refinement, a local one at every edge, or a lift. Hierarchy(PathDependentRefinement(1)) from the one-node graph walks the De Bruijn hierarchy; Hierarchy(CompositionLift(1)) is the refinement of Jongeneel & Jungers (§IV-A), accepted only where the lift is_valid for the template on the system, since an invalid one may worsen the bound.

source
PathCompleteCertificates.RefineTightEdges — Type
RefineTightEdges(refinements = (ForwardEdgeSplit(), BackwardEdgeSplit(),
                                ForwardEdgeProduct(), BackwardEdgeProduct()))

The rule of Athanasopoulos & Jungers: every local refinement at every tight edge, as candidates. Meant for select = :best in refine, which solves each and keeps the best — their Example 2 reaches stability in fifteen such steps on a polyhedral template. A split is proposed only where it changes the graph: a node with a single outgoing (incoming) edge is not split along it.

source
PathCompleteCertificates.SplitTightNode — Type
SplitTightNode(refinement = ForwardEdgeSplit(); rng = nothing)

The rule of Ninite & Jungers (Algorithm 1): split the node held at the most tight outgoing edges, with refinement on its out-star. One candidate, or none when no node holds two — which with one mode per edge is exactly the hypothesis of is_jsr_exact, so the search drying up is itself the certificate.

Ties go to the cheapest split, the node with the fewest outgoing edges, since the split adds one node per edge, and then to the lowest-numbered node, so a run is deterministic. Pass an rng to break the remaining ties at random instead.

source

The loop

PathCompleteCertificates.DEPTH_REACHED — Constant
DEPTH_REACHED

depth_max certificates were solved with the search still making progress.

source
PathCompleteCertificates.EXHAUSTED — Constant
EXHAUSTED

The strategy proposed no candidate — nothing was left to refine — and the gap had not closed. With the default strategy and one mode per edge this cannot happen without OPTIMAL: no node held at two tight outgoing edges is Theorem 4's hypothesis. With another strategy it is a genuine outcome, a dead end that proves nothing.

source
PathCompleteCertificates.OPTIMAL — Constant
OPTIMAL

The optimality_gap closed: the certificate is proved as good as any graph could make it, and the run stopped because it had nothing left to prove. For stability, rates(trace)[end] is then the joint spectral radius, not merely a bound on it — reached either by the cycle bracket of jsr_lower_bound, sound whatever atol was, or by is_jsr_exact, Theorem 4 of Ninite & Jungers.

source
PathCompleteCertificates.STALLED — Constant
STALLED

stall_max steps in a row failed to improve the objective. A graph already attaining the exact joint spectral radius holds every edge tight, so it always looks splittable and would otherwise be grown forever at a constant bound.

source
PathCompleteCertificates.STOPPED — Constant
STOPPED

The stop predicate held on the last certificate — for stability, the rate fell below 1 when stop = c -> c.rate < 1, already a proof.

source

PathCompleteCertificates.refine — Method
refine(template, problem; optimizer, kwargs...)
refine(template, graph, problem; optimizer, strategy = SplitTightNode(),
       select = :first, stop = Returns(false), depth_max = 5, stall_max = 1,
       atol = 1e-4, gap_tol = 1e-6, rtol = 1e-6, path_complete = true,
       kwargs...)

Iteratively refine graph to tighten the certificate it carries, until the problem's optimality_gap closes or the search runs out.

Without a graph, the run starts from common_graph of the system: the one-node graph under arbitrary switching, the automaton itself under constrained switching.

Each step solves best_certificate — jsr_bound for stability — and hands the certificate to strategy, any callable (certificate; atol) -> Vector{Refined} returning candidate graphs, best guess first. The default SplitTightNode splits the node held at the most tight outgoing edges; RefineTightEdges tries every local refinement at every tight edge; Hierarchy applies one step to the whole graph. select takes the first candidate, or with :best solves every candidate and keeps the lowest objective — one solve per candidate, the rule of Athanasopoulos & Jungers.

Returns a RefinementTrace.

Stopping

  • optimality_gap≤ gap_tol → OPTIMAL. Checked every step, not only when the search runs dry: a graph can be optimal long before it is structurally exhausted, and for stability the cycle bracket does not depend on atol being right;
  • stop(certificate) → STOPPED, an explicit request taken before the gap; c -> c.rate < 1 stops a stability run at the first proof of stability;
  • stall_max steps in a row not improving the objective by more than rtol → STALLED. Raise stall_max to cross a plateau;
  • depth_max certificates solved → DEPTH_REACHED;
  • no candidate → EXHAUSTED. With the default strategy and one mode per edge this coincides with OPTIMAL, since "no node holds two tight outgoing edges" is Theorem 4's hypothesis, and the gap is tested first.

The tolerances

rtol is the solve tolerance forwarded to best_certificate — the bisection tolerance of each jsr_bound call — and atol decides tightness. atol ≥ 10 rtol is enforced: bisection stops just above the optimum, so an active edge measures about the bisection gap, not zero. Below a decade the tight subgraph can come out empty, every node then satisfies is_jsr_exact vacuously, and the run certifies a bound that is not the joint spectral radius.

path_complete decides the starting graph only: a refinement of a path-complete graph is path-complete, so the loop does not re-decide it. Other keywords go to best_certificate.
