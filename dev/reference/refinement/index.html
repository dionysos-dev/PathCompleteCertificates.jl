Refinement reference

refine is an algorithm that applies lifts where a certificate is tight; see Graph refinement.

The interface

PathCompleteCertificates.AbstractRefinementAlgorithm — Type
AbstractRefinementAlgorithm

How refine chooses the next graph: next_graph reads a certificate and returns a lifted graph, and initial_graph says where a run starts.

source
PathCompleteCertificates.initial_graph — Method
initial_graph(algorithm, system)

The graph refine(template, problem) starts from: common_graph of system unless algorithm says otherwise.

source
PathCompleteCertificates.next_graph — Function
next_graph(algorithm, certificate; atol, solve) -> Union{Nothing, Tuple{Lifted, Any}}

The graph refine moves to after certificate, as a Lifted, with its certificate when algorithm solved it to choose and nothing otherwise; or nothing alone when the algorithm has no next graph. The loop takes what it returns. atol decides which edges are tight, and solve(lifted) returns the certificate on a candidate.

source

The algorithms

PathCompleteCertificates.TightNodeSplitting — Type
TightNodeSplitting(; rng = nothing)

Algorithm 1 of (Ninite and Jungers, 2026): the forward lift, ForwardSplitLift at a node, of the node with the most tight outgoing edges, among those with at least two. Ties go to the node with the fewest outgoing edges, then the lowest index, or at random with rng. A node with a single successor is passed over, since its forward lift is the graph itself. No candidate is left when no node remains.

initial_graph is the dual of de_bruijn(1, n_modes), as in the experiments of (Ninite and Jungers, 2026): from the one-node graph, whose only successor is itself, the forward lift changes nothing.

source
PathCompleteCertificates.BestTightEdgeLifting — Type
BestTightEdgeLifting(lifts = (ForwardSplitLift(), BackwardSplitLift(),
                              ForwardProductLift(), BackwardProductLift()))

The procedure of (Athanasopoulos and Jungers, 2019; Ex. 2): every lift of lifts at every tight edge where it changes the graph, each candidate solved, and the one with the lowest objective kept. Candidates with words on their edges are left out when the problem accepts only one mode per edge.

source
PathCompleteCertificates.Hierarchy — Type
Hierarchy(lift)

lift applied to the whole graph at every step. From the one-node graph, PathDependentLift(1) walks the de_bruijn graphs (Philippe et al., 2016), and CompositionLift(1) the composition lifts of (Jongeneel and Jungers, 2025; §IV-A). Throws unless lift is_valid for the template on the system.

PathCompleteCertificates.refine — Method
refine(template, problem; optimizer, kwargs...)
refine(template, graph, problem; optimizer, algorithm = TightNodeSplitting(),
       stop = Returns(false), depth_max = 5, stall_max = 1, atol = 1e-4,
       gap_tol = 1e-6, rtol = 1e-6, path_complete = true, kwargs...)

Refine graph, by default initial_graph(algorithm, system), until the optimality_gap of its certificate closes; returns a RefinementTrace. At each step next_graph of algorithm gives the next graph, a lift of the current one.

  • The run stops when stop(certificate) holds, the gap is at most gap_tol, stall_max steps in a row fail to improve the objective by rtol, depth_max graphs are visited, or no candidate is left.
  • rtol is the solve tolerance and atol decides tightness, with atol ≥ 10 rtol.
  • path_complete = false skips the path-completeness check of the starting graph.

Other keywords go to best_certificate.
