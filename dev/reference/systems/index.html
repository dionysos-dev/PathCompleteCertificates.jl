Systems and the common function

A switched system is the input to every problem. The common function, common, is the single function the node functions of a certificate combine into, which certificate(x) evaluates.

Systems

PathCompleteCertificates.dual — Method
dual(system)

The system with every mode matrix transposed and, when switching is constrained, the automaton reversed. A certificate for it on the dual graph in the dual template is a certificate for system (Debauche, Lemma 6.25).

Defined for input-free systems only.

Whether every mode matrix has full rank. Composition with the dynamics keeps a node function positive definite only then, which is what the composition lifts require.

The state matrix of one mode, or the product $A_{i_k} ⋯ A_{i_1}$ along a word (i_1, …, i_k) — the dynamics an edge of a WordGraph imposes its inequality on.

source
PathCompleteCertificates.switched_system — Function
switched_system(A; automaton = nothing)
switched_system(A, B; automaton = nothing)

A discrete-time switched linear system, x⁺ = A_σ x or x⁺ = A_σ x + B_σ u, as a HybridSystems.HybridSystem.

A and B are indexed by mode. automaton restricts which switching sequences are admissible; the default admits every sequence. The switching signal is never chosen; the input u, when there is one, is.

Read the matrices back with mode_matrices and input_matrices.

A = [[1.0 0.0; 0.0 0.5], [0.5 0.0; 0.0 1.0]]
B = [reshape([1.0, 0.0], 2, 1), reshape([0.0, 1.0], 2, 1)]
switched_system(A, B)

Trajectories and simulation

PathCompleteCertificates.Trajectory — Type
Trajectory

One run of a switched system: the states visited, the switching sequence taken, and the inputs applied if there were any.

states holds one more entry than switching — it starts at the initial state and ends after the last transition. inputs is nothing for an open-loop run, and otherwise holds one input per step.

source

has_input(trajectory) -> Bool

Whether the run applied an input.

source
PathCompleteCertificates.inputs — Method
inputs(trajectory)

The inputs applied, one per step, or nothing for an open-loop run; has_input says which.

source
PathCompleteCertificates.states — Method
states(trajectory)

The states visited, oldest first. One longer than switching.

source
PathCompleteCertificates.switching — Method
switching(trajectory)

The switching sequence taken, as modes. One shorter than states: entry k is the mode that carried states(trajectory)[k] to states(trajectory)[k + 1].

PathCompleteCertificates.simulate — Method
simulate(system, x0, modes; u = nothing)
simulate(system, x0, horizon::Integer; u = nothing, discrete_state = 1, rng = Random.default_rng())

Run system from x0 along a switching sequence and return a Trajectory: x[k+1] = A_{modes[k]} x[k], or, once system has an input, x[k+1] = A_{modes[k]} x[k] + B_{modes[k]} u[k].

Given modes explicitly, that sequence is taken. Given a horizon instead, a sequence of that length is drawn: a random walk on system's automaton, starting at discrete_state and, at each step, picking uniformly among the transitions leaving the current state. A system built with a restricted automaton therefore only ever produces a sequence that automaton admits, never an inadmissible one.

The drawn sequence is read back with switching.

u is required exactly when has_input(system); passing one for an autonomous system, or omitting it for a controlled one, throws. It is either a sequence of inputs, as long as the switching sequence and indexed like it, or a memoryless feedback law u(x), called on the current state at each step.

The policy of an OptimalControlCertificate has memory, a node of the certificate graph, so it is not a u(x); simulate(certificate, x0, steps) runs it.

source
PathCompleteCertificates.simulate — Method
simulate(certificate, x0, steps; rng = Random.default_rng(), node = nothing)

Run the closed loop under the policy an OptimalControlCertificate carries, and return a Trajectory whose inputs are the inputs applied. The mode at each step is drawn from the modes the system's automaton admits, as in the open-loop method.

The policy has memory: the gains are indexed by node of the certificate graph, and that node advances along the observed mode, so the run tracks the state, the automaton state and the graph node at once. A memoryless law u(x) cannot express it, which is why it is not the u keyword of the open-loop method.

node is the node of the certificate graph the policy starts in. By default it is the node whose function attains certificate(x0), so the run is bounded by the common bound at the initial state. Where the graph offers several successors for the observed mode the first is taken; on a De Bruijn graph the successor is unique.

The common function

PathCompleteCertificates.common — Method
common(template, graph, problem, Ps, x)

Evaluate at x the common function the node functions Ps of a certificate on graph combine into (Philippe, Athanasopoulos, Angeli & Jungers): the minimum over the nodes on a complete graph (Cor. III.3), the maximum on a co-complete one, and a minimum of maxima over the observer construction otherwise (Thm. III.8). Depending on problem it is a common Lyapunov function, a common barrier function, or an upper bound on the value function.
