System reference

A switched system is the input to every problem. See Systems and problems for the concepts.

PathCompleteCertificates.PathCompleteCertificates — Module
PathCompleteCertificates

Certificates for switched systems built on path-complete graphs: a labelled graph, a function from a template at each node, and one inequality per edge.

source

Trajectories and simulation

PathCompleteCertificates.Trajectory — Type
Trajectory

One run of a switched system: the states visited, the switching sequence taken and the inputs applied, nothing if there were none. Its length is the number of steps.

source
PathCompleteCertificates.has_input — Method
has_input(trajectory) -> Bool

Whether the run applied an input.

source
PathCompleteCertificates.inputs — Method
inputs(trajectory)

The inputs applied, one per step, or nothing for an open-loop run.

source
PathCompleteCertificates.states — Method
states(trajectory)

The states visited, oldest first, one more than the steps.

source
PathCompleteCertificates.switching — Method
switching(trajectory)

The modes taken: entry k carried states(trajectory)[k] to states(trajectory)[k + 1].

source
PathCompleteCertificates.simulate — Method
simulate(system, x0, modes; u = nothing)
simulate(system, x0, horizon::Integer; u = nothing, rng = Random.default_rng())

Run system from x0 along modes, or along horizon modes drawn uniformly at random, and return a Trajectory. u, a vector of inputs or a feedback law u(x), is required exactly when has_input(system); otherwise it throws.
