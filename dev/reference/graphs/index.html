Graph reference

The certificate graph is a HybridSystems.GraphAutomaton, the same type as the automaton of a constrained system, or a WordGraph when its edges read words. The argument name says which is wanted: graph is the certificate's, system carries its own. See Path-complete graphs for what the predicates mean.

Queries

PathCompleteCertificates.CertificateGraph — Type
CertificateGraph

The graph types a certificate is built on: a HybridSystems.GraphAutomaton, whose labels are modes, or a WordGraph, whose labels are words.

A certificate graph and a system's automaton share the first type; the argument name says which is wanted: graph is the certificate's, system carries its own.

source
PathCompleteCertificates.WordGraph — Type
WordGraph(n_nodes)

A labelled graph whose edges carry words: finite sequences of modes, a mode being a word of length one.

Built like a GraphAutomaton, with add_edge! taking a vector of modes for the label. A word edge (s, d, w) imposes one inequality, on the product of the modes along w, and costs no node — which is what the edge products of ForwardEdgeProduct buy. Every query of this file accepts one; label returns the word.

Path-completeness of a word graph is decided on its expanded_form. Stability accepts word graphs; safety, optimal control and common do not, since they need the state at every step.

PathCompleteCertificates.alphabet — Method
alphabet(graph)

The distinct modes appearing on the edges of graph — every letter of every word — the switching alphabet it can read.

This is the alphabet the graph uses, which is not in general the system's. A graph that never mentions a mode has a smaller alphabet and is not path-complete for a system that has it, so pass the system's language explicitly to is_path_complete rather than relying on this.

Word graphs

PathCompleteCertificates.expanded_form — Method
expanded_form(graph) -> (expanded, origins)

The graph with one mode per edge obtained by breaking every word edge (s, d, i₁…iₖ) into a chain s → m₁ → ⋯ → mₖ₋₁ → d through k − 1 fresh nodes (Ahmadi et al. 2014, Def. 2.1; Debauche, Def. 6.7).

origins[m] is the node of graph a node m came from, and 0 for a fresh one. A graph with one mode per edge expands to itself.

A word graph is path-complete exactly when its expanded form is, which is how is_path_complete decides it. The two certify the same rate for a template closed under composition with the dynamics, the word graph with fewer variables (Debauche, Prop. 7.70).

Predicates

PathCompleteCertificates.is_co_complete — Method
is_co_complete(graph)
is_co_complete(graph, alphabet)

The dual of is_complete: every node has an incoming edge for every letter of alphabet. Also sufficient but not necessary for path-completeness, and it licenses the maximum of Corollary III.3. The dual De Bruijn graph is co-complete.

source
PathCompleteCertificates.is_complete — Method
is_complete(graph)
is_complete(graph, alphabet)

Whether every node has an outgoing edge for every letter of alphabet — Definition III.2 of Philippe et al.

This is sufficient but not necessary for is_path_complete: a graph can read every word without every node reading every letter. It is what licenses the plain minimum of Corollary III.3, which is how common combines on a complete graph.

A statement about letters, so a WordGraph with a longer word is never complete.

source
PathCompleteCertificates.is_path_complete — Method
is_path_complete(graph)
is_path_complete(graph, alphabet)
is_path_complete(graph, automaton)

Whether every switching sequence of the language is readable in graph — Definition II.1 of Philippe, Athanasopoulos, Angeli & Jungers: for any $k ≥ 1$ and any $σ_1 … σ_k$ over the alphabet there is a path $(s_i, s_{i+1}, σ_i)_{i=1..k}$ in the graph.

This is what makes a certificate speak for the whole system: the edge inequalities certify the property over the language the graph reads, which is every admissible sequence exactly when the graph is path-complete.

It is not graph-theoretic completeness, where every pair of vertices is adjacent, and it is strictly weaker than is_complete — see that docstring.

Decided by the subset construction: a word is readable from some node exactly when the set of nodes reachable by it is nonempty, so the graph is path-complete iff the subset construction started from all nodes never reaches the empty set. That is a finite search, since there are finitely many subsets.

The second argument says which switching sequences must be readable. Under arbitrary switching it is the alphabet, and every sequence of modes over it must be; under constrained switching it is the system's automaton, and every path of the automaton must be, which the same construction decides in product with it. Pass language of the system whenever the question is about a certificate: without a second argument the alphabet is the modes graph happens to use, so a graph that never mentions a mode passes for its own labels and is not path-complete for a system that has that mode.

A WordGraph is path-complete when its expanded_form is: every word of the language is then a factor of the label of some path.

Languages

PathCompleteCertificates.common_graph — Method
common_graph(system)

The common Lyapunov function graph $G_0$ of the system (Debauche, Della Rossa & Jungers, Prop. 2): one node with a loop per mode, on which a certificate is a single common function, and which every path-complete graph is no worse than. Under constrained switching its counterpart is the system's own automaton, one function per state (Philippe, Essick, Dullerud & Jungers), and that is what is returned.

Either reads the system's language by construction, and every refinement preserves that, so refine starts here and never re-decides path-completeness.

source
PathCompleteCertificates.language — Method
language(system)

The switching language of system, as its automaton: a OneStateAutomaton reading every word over the modes when switching is arbitrary, the constraint automaton passed to switched_system otherwise.

This is what is_path_complete must be asked against when the question is about a certificate, and every problem asks it.

Simulation

PathCompleteCertificates.simulation — Method
simulation(G, H) -> Union{Nothing, Vector{Int}}

A map R from the nodes of H to those of G with (R(a), R(b), i) an edge of G for every edge (a, b, i) of H — Definition 3.1 of Philippe & Jungers — or nothing when none exists. G then simulates H.

Simulation decides the ordering that holds for every template and every system (their Theorem 3.5): H is no worse than G for all of them exactly when G simulates H. The map is found by backtracking inside the greatest simulation relation between the nodes, the one MinLift decides with. One mode per edge.

Constructions

PathCompleteCertificates.de_bruijn — Method
de_bruijn(order, n_modes)

The primal De Bruijn graph of order order on n_modes modes: a node per tuple of order modes, the last ones read, newest first, and from (i₁, …, iₗ) an edge reading σ to (σ, i₁, …, iₗ₋₁) (Ninite & Jungers, Def. 6; Debauche, Def. 6.10, which writes the tuple oldest first). It is complete, with n_modes^order nodes, and path-complete. The dual De Bruijn graph, co-complete, is dual(de_bruijn(order, n_modes)).

source
PathCompleteCertificates.observer_graph — Method
observer_graph(graph) -> (observer, states)
observer_graph(graph, alphabet) -> (observer, states)

The subset construction of graph from the set of all its nodes: a node of the observer per nonempty subset reached, states[k] being the subset node k stands for, and an edge (P, Q, σ) when Q is the set of nodes an edge reading σ leads to from some node of P. Empty subsets are dropped, so the observer is complete for alphabet exactly when graph is path-complete for it, which is how is_path_complete decides. It is the graph on which Theorem III.8 of Philippe, Athanasopoulos, Angeli & Jungers states the common function of a graph that is neither complete nor co-complete, which is how common reads it. alphabet defaults to the modes graph uses.

source
PathCompleteCertificates.simple_cycles — Method
simple_cycles(graph; max_length = n_nodes(graph))

Every simple cycle of graph of at most max_length edges, each as the sequence of transitions traversed.

Simple means no node is visited twice, so a cycle of k edges passes through k distinct nodes. Each is returned once, written from its lowest-numbered node. A graph can have exponentially many simple cycles; max_length bounds the search.
