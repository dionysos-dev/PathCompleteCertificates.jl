Problem reference

A problem fixes the inequality imposed along each edge of the graph. See Problems for the concepts. A certificate c is callable: c(x) evaluates its common function, common.

The interface

PathCompleteCertificates.AbstractProblem — Type
AbstractProblem

A property to certify, defined by the inequality imposed along each edge.

PathCompleteCertificates.best_certificate — Method
best_certificate(template, graph, problem; optimizer, rtol, kwargs...)

The certificate refine solves on each graph: for stability that of smallest rate, from jsr_bound to relative tolerance rtol; for a problem certified by one solve, that of certify, and rtol is ignored.

Build and solve the model, and return an AbstractCertificate. Check is_feasible before reading it.

The problem on the dual system. Throws for every problem but stability.

Build, without solving, the JuMP model that certify solves.

Certificates

PathCompleteCertificates.AbstractCertificate — Type
AbstractCertificate

The result of certify: node functions on a graph, and the value certified (rate, margin or gains). A certificate c is callable: c(x) is common(template(c), graph(c), problem(c), functions(c), x).

source
PathCompleteCertificates.CertificateData — Type
CertificateData(problem, template, graph, functions, status, feasible)

The fields shared by every certificate.

source
PathCompleteCertificates.common — Method
common(template, graph, problem, Vs, x)

The common function of the node functions Vs on graph, evaluated at x: a minimum of maxima of the Vs (Philippe et al., 2017). Depending on problem, a common Lyapunov function, a common barrier function or a bound on the value function.

source
PathCompleteCertificates.dual — Method
dual(certificate)

The certificate on the dual graph made of the dual norms of the node functions. Throws for every problem but stability.

source
PathCompleteCertificates.edge_slacks — Function
edge_slacks(certificate)

The slack of every edge inequality, in edges(graph(certificate)) order; zero means tight. Throws on an infeasible certificate.

source
PathCompleteCertificates.functions — Method
functions(certificate)

The fitted node function at each node, indexed by node.

source
PathCompleteCertificates.graph — Method
graph(certificate)

The path-complete graph the certificate is built on.

is_feasible(certificate) -> Bool

Whether the solve produced a certificate. false means none exists in this template on this graph, not that the property fails.

objective(certificate) -> Real

The value refine minimises: the rate, for stability.

optimality_gap(certificate; kwargs...) -> Real

Tight edges

PathCompleteCertificates.tight_edges — Method
tight_edges(certificate; atol = 1e-4)

The edges of the certificate's graph whose slack is at most atol, in edges(graph(certificate)) order. atol is absolute, so its meaning depends on the scale of the certificate.

source
PathCompleteCertificates.tight_subgraph — Method
tight_subgraph(certificate; atol = 1e-4)

The subgraph, on the same nodes, of the edges whose slack is at most atol.

source

Stability

PathCompleteCertificates.StabilityCertificate — Type
StabilityCertificate

A path-complete Lyapunov function and its rate, an upper bound on the joint spectral radius.

source
PathCompleteCertificates.StabilityProblem — Type
StabilityProblem(system)

Stability problem for an input-free switched linear system, certified at a given rate by certify or at the smallest rate by jsr_bound.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem::StabilityProblem; optimizer, rate = 1)

Solve the stability problem at the fixed rate.

source
PathCompleteCertificates.dual — Method
dual(certificate::StabilityCertificate)

The certificate on the dual graph made of the dual norms of the node functions, at the same rate. Requires a template that has_dual.

source
PathCompleteCertificates.is_jsr_exact — Method
is_jsr_exact(certificate; atol = 1e-4) -> Bool

Whether every node has at most one outgoing edge in the tight_subgraph, which proves the rate is the joint spectral radius (Ninite and Jungers, 2026; Thm. 4). false means unknown. At the optimal rate the tight subgraph keeps the rate (Ninite and Jungers, 2026; Prop. 1), so it contains a cycle; without one, atol was too small to see the active edges and the answer is false. Throws on a graph with words; use expanded_form.

source
PathCompleteCertificates.jsr_bound — Method
jsr_bound(template, graph, problem; optimizer, rtol = 1e-3,
          max_iterations = 100, initial_upper = 1.0)

The StabilityCertificate of the smallest feasible rate, to relative tolerance rtol. initial_upper is a first guess of a feasible rate.

source
PathCompleteCertificates.jsr_lower_bound — Method
jsr_lower_bound(certificate; atol = 1e-4, max_length = nothing)

A lower bound on the joint spectral radius, valid for any atol: the largest ρ(A_w)^{1/|w|} over the words w read along the simple cycles of at most max_length edges of the tight_subgraph; 0 if there are none.

source
PathCompleteCertificates.optimality_gap — Method
optimality_gap(certificate::StabilityCertificate; atol = 1e-4, max_length = nothing)

How far the rate is known to be from the joint spectral radius: 0 when is_jsr_exact holds, otherwise the rate minus jsr_lower_bound.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer, rate = 1)

The feasibility problem V_b(A_w x) <= rate^(p |w|) * V_a(x) for every edge (a, b, w), with p the template's degree and |w| the length of the word.

Safety

PathCompleteCertificates.SafetyCertificate — Type
SafetyCertificate

A path-complete barrier function, its margin of separation between the initial and unsafe sets (positive when safety is certified), and the S-procedure multipliers initial_multipliers and unsafe_multipliers, one per node.

source
PathCompleteCertificates.SafetyProblem — Type
SafetyProblem(system, S0, Su)

Safety problem for an input-free switched linear system (Anand et al., 2024), with initial and unsafe sets {x : [x; 1]' S [x; 1] ≥ 0} for S = S0, Su. The barrier at node v is [x; 1]' P_v [x; 1] with P_v symmetric, not necessarily positive semidefinite.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer)

Solve the barrier program and return a SafetyCertificate.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer)

Build, without solving, the barrier program; only QuadraticTemplate is supported.

source

Optimal control

PathCompleteCertificates.OptimalControlCertificate — Type
OptimalControlCertificate

A state-feedback policy, u = gains[a] * x at node a, and an upper bound on its value function, the minimum of the node quadratic forms. Calling the certificate c as c(x) evaluates this bound.

source
PathCompleteCertificates.OptimalControlProblem — Type
OptimalControlProblem(system, Q, R)

Quadratic optimal-control problem for a switched linear system with an input (Ninite et al., 2026). The stage cost is x'Q*x + u'R*u, with Q and R symmetric positive definite.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer, psd_margin = 1e-4)

Synthesise a state-feedback policy and a bound on its value function, returned as an OptimalControlCertificate. Only complete graphs and QuadraticTemplate are supported; the solver maximises Σᵢ log det Pᵢ⁻¹.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer, psd_margin = 1e-4)

Build, without solving, the optimal-control program in S = P⁻¹, Y = KS. Only complete graphs and QuadraticTemplate are supported. psd_margin is the strictness of every matrix inequality.

source
PathCompleteCertificates.simulate — Method
simulate(certificate::OptimalControlCertificate, x0, modes; node = nothing)
simulate(certificate::OptimalControlCertificate, x0, horizon::Integer;
         rng = Random.default_rng(), node = nothing)

Run the closed loop under the policy of certificate along modes, or along horizon modes drawn uniformly at random, and return a Trajectory. The gain applied is that of the current graph node, which follows the observed modes from node, by default the node whose function is smallest at x0.
