The interface and the certificates

PathCompleteCertificates.AbstractCertificate — Type
AbstractCertificate

What a problem hands back: the fitted node functions, plus whatever that problem certifies as a field of its own, rate, margin or gains. The shared part is a CertificateData, read by the accessors below.

A certificate is callable: certificate(x) is common at x.

source
PathCompleteCertificates.AbstractProblem — Type
AbstractProblem

What is proved: a problem determines the edge inequality, templates the family the node functions are drawn from.

source
PathCompleteCertificates.CertificateData — Type
CertificateData(problem, template, graph, functions, status, feasible)

The part of a certificate that does not depend on which problem produced it.

source
PathCompleteCertificates.add_edge_constraint! — Function
add_edge_constraint!(model, problem, template, V_src, V_dst, dynamics; scale = 1)

Add this problem's certificate inequality for one edge, dynamics being the matrix the edge reads: the product along its word.

One method per problem, generic in the template: compose the template's primitives rather than dispatching on a template here. scale is the factor on the source side a driver varies, already raised to the template's degree and the word's length; stability passes rate^(d·|w|). A problem with no such factor ignores it.

source
PathCompleteCertificates.best_certificate — Method
best_certificate(template, graph, problem; optimizer, kwargs...)

The certificate refine repeats on each graph: the problem's own driver. The default is certify; stability's is jsr_bound, which bisects on the rate, so rtol is accepted here and ignored by problems that do not bisect.

source
PathCompleteCertificates.certify — Function
certify(template, graph, problem; optimizer, kwargs...)

Solve for the guarantee, and return an AbstractCertificate.

One entry point for every problem: build the model, solve it, and read the result back. What each problem certifies is a typed field on the certificate it returns — rate, margin, gains.

Check is_feasible before reading anything else. An infeasible result is still a certificate object, carrying the solver status so that "no certificate exists in this template on this graph" is distinguishable from "the solver gave up".

source
PathCompleteCertificates.dual — Method
dual(problem)
dual(certificate)

The problem on the dual system, and the certificate it has on the dual graph in the dual template, made of the dual norms of the node functions at the same nodes — nothing is solved (Debauche, Lemma 6.25).

Stability defines both; a problem whose edge inequality is not a norm inequality has no dual, and these throw.

source
PathCompleteCertificates.edge_slacks — Function
edge_slacks(certificate)

The slack of every edge inequality, in edges(graph(certificate)) order.

Zero means the edge is tight: the certificate is held at exactly that inequality. A large value means the edge is not what limits the bound. One method per problem, each through domination_slack with the edge's own map and scale; a problem whose edge does not factor through add_domination! has none.

Throws on an infeasible certificate, which has no fitted functions to measure.

graph(certificate)

The path-complete graph the certificate is built on.

PathCompleteCertificates.is_feasible — Method
is_feasible(certificate) -> Bool

Whether the solve produced a certificate.

PathCompleteCertificates.node_value — Method
node_value(template, problem, V, x)

Evaluate one fitted node function at x. Node functions are callable, so the default is V(x). It is on the problem axis because a problem may lift the value into other coordinates: SafetyProblem evaluates its barriers at [x; 1], the one pair with a method of its own.

PathCompleteCertificates.objective — Function
objective(certificate) -> Real

What a problem minimises across graphs, smaller being better: the rate for stability, minus the margin for safety. refine compares steps on it.

source
PathCompleteCertificates.optimality_gap — Method
optimality_gap(certificate; kwargs...) -> Real

How far the certificate is known to be from the best any graph could do — zero when it is proved optimal, Inf when the problem has no lower bound, which is the default. refine stops with OPTIMAL when it closes.

Stability supplies the cycle bracket of jsr_lower_bound and the structural test of is_jsr_exact.

PathCompleteCertificates.optimization_model — Function
optimization_model(template, graph, problem; optimizer, kwargs...)

Build the JuMP model this problem and template induce on graph, without solving it.

One method per problem. Use it to inspect the program, add your own constraints, or change the objective before handing it to JuMP.optimize!; certify is this plus the solve and the extraction.

PathCompleteCertificates.tight_edges — Method
tight_edges(certificate; atol = 1e-6)

The edges whose inequality is active, as (source, destination, label) tuples: the edges that hold the certificate up. A node with two or more tight outgoing edges is the one a refinement step splits, since it serves two futures with a single function. atol is absolute, and a certificate is only determined up to scale, so read it against edge_slacks.

source
PathCompleteCertificates.tight_subgraph — Method
tight_subgraph(certificate; atol = 1e-6)

The subgraph of the edges whose inequality is active, on the same nodes, so node numbers carry over. For stability it is Definition 4 of Ninite & Jungers, Ē = {(a,b,i) ∈ E : λ_min(γ²P_a − Aᵢᵀ P_b A_i) = 0}, the object is_jsr_exact reads the out-degrees of and jsr_lower_bound the cycles. atol stands in for the exact zero, which a bisected solution never reaches; see refine on choosing it.

Stability

PathCompleteCertificates.StabilityCertificate — Type
StabilityCertificate

A path-complete Lyapunov function and the contraction rate it certifies.

rate is an upper bound on the joint spectral radius: every switching sequence contracts at least this fast under the node functions. It is the smallest rate the bisection in jsr_bound could certify with this template on this graph, so a larger value says the template is conservative, not that the system is slower.

functions(certificate) are the node Lyapunov functions and certificate(x) the common one.

source
PathCompleteCertificates.StabilityProblem — Type
StabilityProblem(system)

Stability problem for an input-free switched linear system.

The problem stores the system only; the rate is given to certify or bisected on by jsr_bound.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem::StabilityProblem; optimizer, rate = 1)

Solve the fixed-rate Lyapunov feasibility problem once; is_feasible of the result says whether the system contracts at that rate on this graph in this template. jsr_bound bisects on rate on top of it.

source
PathCompleteCertificates.dual — Method
dual(certificate::StabilityCertificate)

The certificate on dual(graph) for dual(problem) in dual(template) made of the dual norms of the node functions, at the same rate (Debauche, Lemma 6.25).

Each edge inequality V_d(A_i x) ≤ γ V_s(x) is, by duality of norms, V_s*(A_iᵀ x) ≤ γ V_d*(x): the inequality of the reversed edge. Nothing is solved, and an edge of the result is tight exactly when its reverse was. An infeasible certificate dualises to an infeasible one with the same status.

Requires a template that has_dual.

source
PathCompleteCertificates.is_jsr_exact — Method
is_jsr_exact(certificate; atol = 1e-6) -> Bool

Whether the certificate's rate is the exact joint spectral radius, by the optimality certificate of Ninite & Jungers (Theorem 4): if every node has at most one outgoing edge in the tight_subgraph, then γ*(G) = ρ(A).

The constrained precedent is Theorem 3.8 of Philippe, Essick, Dullerud & Jungers, where the tight edges form a simple cycle. One mode per edge: the theorem is not proved with words on the edges, and jsr_lower_bound needs no such proof.

Sufficient, not necessary — and `atol`-dependent

false means unknown, never "inexact". A graph can attain the exact rate with every edge tight, where the condition cannot hold: two opposite rotations scaled by 0.9 do exactly that.

And the test is only as good as atol. Too small, and genuinely active edges are missed, the subgraph is too thin, and this returns true without grounds. jsr_lower_bound is the tolerance-free alternative: it brackets the answer instead of asserting it.

source
PathCompleteCertificates.jsr_bound — Method
jsr_bound(template, graph, problem; optimizer, rtol = 1e-3,
          max_iterations = 100, initial_upper = 1.0)

Estimate an upper bound on the joint spectral radius by bisection.

At each candidate rate, solve the fixed-rate feasibility problem.

Returns a StabilityCertificate. Its rate is the smallest feasible bound found to relative tolerance rtol; functions(certificate) are the node Lyapunov functions, and certificate(x) evaluates the common one.

source
PathCompleteCertificates.jsr_lower_bound — Method
jsr_lower_bound(certificate; atol = 1e-6, max_length = nothing)

A lower bound on the joint spectral radius, from the cycles of the tight_subgraph.

A cycle (a₁,a₂,w₁) … (a_k,a₁,w_k) of the graph forces γ ≥ ρ(A_{w_k} ⋯ A_{w_1})^{1/ℓ} with ℓ the number of modes read along it, and any product of modes bounds the joint spectral radius from below (Philippe, Essick, Dullerud & Jungers, Lemma 3.7; Ninite & Jungers, Lemma 1 and its proof). The largest such value over the cycles found is returned; 0 when there are none.

Together with the certificate's own rate — an upper bound — this brackets the answer, and the bracket holds whatever atol was: a cycle of the tight subgraph is still a cycle of the graph, so its bound is valid even if the tight set was identified badly. atol only decides where to look for good cycles, and max_length how far; both affect how tight the bound is, neither whether it is true.

max_length defaults to the number of nodes, which enumerates every simple cycle; the count grows quickly with the graph, so lower it on a large one. A truncated search weakens the bound without making it wrong.

source
PathCompleteCertificates.optimality_gap — Method
optimality_gap(certificate::StabilityCertificate; atol = 1e-4, max_length = nothing)

How far the rate is known to be from the joint spectral radius: 0 when is_jsr_exact holds, and otherwise the rate minus jsr_lower_bound, the cycle bracket. atol reads tightness and max_length bounds the cycle search, as in those two.

The bracket is sound whatever atol was; the structural test is not, and it is skipped on a WordGraph, where it is not yet proved.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer, rate = 1)

The feasibility problem of the Lyapunov inequalities

V_b(A_w x) <= rate^(d |w|) * V_a(x)

for every edge (a, b, w) of graph, d the template's degree of homogeneity and |w| the number of modes the edge reads: one as a rule, the product of the modes along the word on a WordGraph.

The model has no objective: certify solves it once at a rate and jsr_bound bisects on the rate. optimizer must be an LP solver for the copositive and polyhedral templates and an SDP solver for the quadratic one.

source

Safety

PathCompleteCertificates.SafetyCertificate — Type
SafetyCertificate

A path-complete barrier function and the separation it achieves.

margin is how strictly the barrier is negative on the initial set and positive on the unsafe one. It is strictly positive exactly when the barrier certifies anything; at zero the two sets are not separated. The barriers are scale-normalised, so it is comparable between graphs rather than an arbitrary number.

initial_multipliers and unsafe_multipliers are the S-procedure multipliers, one per node.

source
PathCompleteCertificates.SafetyProblem — Type
SafetyProblem(system, S0, Su)

Path-complete safety problem for an input-free switched linear system (Anand, Jungers, Zamani & Allgöwer, CDC 2024).

S0 and Su describe the initial and unsafe sets in homogeneous coordinates, as {x : [x; 1]' S [x; 1] ≥ 0}. The candidate barrier functions are

B_v(x) = [x; 1]' * P_v * [x; 1]

where P_v is symmetric but not necessarily positive semidefinite.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer)

Solve the path-complete barrier optimization problem.

Returns a SafetyCertificate. Its margin is the separation achieved between the initial and unsafe sets, and it is strictly positive exactly when the barrier certifies anything; initial_multipliers and unsafe_multipliers are the S-procedure multipliers.

Optimal control

PathCompleteCertificates.OptimalControlCertificate — Type
OptimalControlCertificate

A jointly synthesised state-feedback policy and the value-function bound it comes with.

gains is one feedback matrix per node: at node a the policy is u = gains[a] * x. The bound on the closed-loop value function is certificate(x), a function of the state, and functions(certificate) are the quadratic forms it is the minimum of.

source
PathCompleteCertificates.OptimalControlProblem — Type
OptimalControlProblem(system, Q, R)

Quadratic optimal-control problem for a switched linear system with an input (Ninite, Banse, Berger & Jungers). The stage cost is x'Q*x + u'R*u, with Q and R symmetric positive definite.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer, psd_margin = 1e-4)

Synthesize a quadratic state-feedback policy and an upper bound on the closed-loop value function for problem. Supports complete graphs and QuadraticTemplate only.

Returns an OptimalControlCertificate: functions(certificate) are the node matrices and gains the feedback gains, one of each per node, and the value-function bound is certificate(x), a function of the state. Among the feasible certificates the solver picks the one of largest volume, by the log-determinant objective Σᵢ log det Pᵢ⁻¹.

source

optimization_model(template, graph, problem; optimizer, psd_margin = 1e-4)

Build the optimal-control program without solving it.

Supports complete graphs and QuadraticTemplate only; see certify for what the solved program yields.
