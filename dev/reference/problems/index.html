Problem reference

A problem fixes the edge inequality, and owns the type of its certificate. See How a certificate works and Reading a certificate for the concepts. A certificate c is callable: c(x) evaluates its common function, common.

The interface

PathCompleteCertificates.AbstractProblem — Type
AbstractProblem

A property to certify, defined by its edge inequality.

source
PathCompleteCertificates.certify — Function
certify(template, graph, problem; optimizer, kwargs...)

Build and solve the model, and return the best AbstractCertificate on graph: the smallest rate for stability, the largest margin for safety, and a policy with a small cost bound for optimal control. Check is_feasible before reading it. refine calls it on every graph it visits.

source
PathCompleteCertificates.dual — Method
dual(problem)

The dual of problem. Throws for a problem that defines no dual.

source
PathCompleteCertificates.node_value — Method
node_value(problem, V, x)

The value of the node function V at the state x: V(x) by default. A problem whose node functions take coordinates other than x defines its own method, such as V([x; 1]) for SafetyProblem, in homogeneous coordinates.

source
PathCompleteCertificates.optimization_model — Function
optimization_model(template, graph, problem; optimizer, kwargs...)

Build, without solving, the JuMP model that certify solves.

source

Certificates

PathCompleteCertificates.AbstractCertificate — Type
AbstractCertificate

The result of certify: node functions on a graph, and what the problem certifies. A certificate c is callable: c(x) returns the value of its common function at x.

source
PathCompleteCertificates.AbstractCertificate — Method
(certificate::AbstractCertificate)(x)

The common function of the certificate at x. Throws on an infeasible certificate.

source
PathCompleteCertificates.CertificateData — Type
CertificateData(problem, template, graph, functions, status, feasible)

The fields shared by every certificate:

  • problem, the problem certified;
  • template, the template the node functions are drawn from;
  • graph, the path-complete graph they sit on;
  • functions, the node function at each node, empty after a failed solve;
  • status, the solver's termination status;
  • feasible, whether the solve produced a certificate, read by is_feasible.
source
PathCompleteCertificates.common — Method
common(graph, problem, Vs, x)

The common function of the node functions Vs on graph, evaluated at x: a minimum of maxima of the Vs (Philippe et al., 2019). Depending on problem, a common Lyapunov function, a common barrier function or a bound on the value function.

source
PathCompleteCertificates.dual — Method
dual(certificate)

The certificate on the dual graph made of the dual norms of the node functions. Throws for a certificate whose problem defines no dual.

source
PathCompleteCertificates.edge_slacks — Function
edge_slacks(certificate)

The slack of every edge inequality, in edges(graph(certificate)) order; zero means tight. For stability, slacks are relative to the scale of the node functions, so they do not depend on its normalization, and a tight edge has a slack of the order of rtol. Throws on an infeasible certificate.

source
PathCompleteCertificates.functions — Method
functions(certificate)

The node function at each node, indexed by node; empty after a failed solve.

source
PathCompleteCertificates.graph — Method
graph(certificate)

The path-complete graph the certificate is built on.

source
PathCompleteCertificates.is_feasible — Method
is_feasible(certificate) -> Bool

Whether the solve produced a certificate. false means none exists in this template on this graph, not that the property fails.

source
PathCompleteCertificates.objective — Function
objective(certificate) -> Real

The number refine aims to lower from one graph to the next, such as the rate of a StabilityCertificate.

source
PathCompleteCertificates.optimality_gap — Method
optimality_gap(certificate; kwargs...) -> Real

An upper bound on how far objective is from the best any graph could reach: 0 when proved optimal, Inf by default.

source
PathCompleteCertificates.problem — Method
problem(certificate)

The problem the certificate was produced for.

source
PathCompleteCertificates.status — Method
status(certificate)

The solver's termination status, for diagnosis. Read is_feasible to know whether the certificate holds: it may accept an almost-optimal solve, or reject a solution the solver reported optimal.

source
PathCompleteCertificates.template — Method
template(certificate)

The template its node functions are drawn from.

Tight edges

PathCompleteCertificates.tight_edges — Method
tight_edges(certificate; atol = 1e-4)

The edges of the certificate's graph whose slack is at most atol, in edges(graph(certificate)) order. For stability, slacks are relative to the scale of the node functions, so atol compares with the rtol of certify: read them with atol at least ten times rtol.

source
PathCompleteCertificates.tight_subgraph — Method
tight_subgraph(certificate; atol = 1e-4)

The subgraph, on the same nodes, of the edges whose slack is at most atol.

source

Stability

PathCompleteCertificates.StabilityCertificate — Type
StabilityCertificate

A path-complete Lyapunov function and its rate, an upper bound on the joint spectral radius.

source
PathCompleteCertificates.StabilityProblem — Type
StabilityProblem(system)

Stability problem for an input-free switched linear system, certified by certify at the smallest rate, or at a given one.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem::StabilityProblem; optimizer, rate = nothing,
        rtol = 1e-6, max_iterations = 100, initial_upper = 1.0,
        check_path_complete = true, conditioning_bound = Inf)

The StabilityCertificate of the smallest feasible rate, an upper bound on the joint spectral radius, found by bisection to relative tolerance rtol, using a SetProg family or a vector of families, one per node. initial_upper is a first guess of a feasible rate. Given a rate, solve at that rate only. A finite conditioning_bound bounds ellipsoid gauge matrices between I and conditioning_bound * I.

rtol is that of refine, so that the default atol of tight_edges is at least ten times it: a certificate read at a coarser rtol needs a larger atol.

source
PathCompleteCertificates.dual — Method
dual(certificate::StabilityCertificate)

The certificate on the dual graph made of the dual norms of the node functions, at the same rate. Requires a template that has_dual.

source
PathCompleteCertificates.is_jsr_exact — Method
is_jsr_exact(certificate; atol = 1e-4) -> Bool

Whether every node has at most one outgoing edge in the tight_subgraph, which proves the rate is the joint spectral radius (Ninite and Jungers, 2026; Thm. 4). false means unknown. At the optimal rate the tight subgraph keeps the rate (Ninite and Jungers, 2026; Prop. 1), so it contains a cycle; without one, atol was too small to see the active edges and the answer is false. Throws on a graph with words; use expanded_form.

source
PathCompleteCertificates.jsr_lower_bound — Method
jsr_lower_bound(certificate; atol = 1e-4, max_length = nothing)

A lower bound on the joint spectral radius, valid for any atol: the largest ρ(A_w)^{1/|w|} over the words w read along the simple cycles of at most max_length edges of the tight_subgraph; 0 if there are none.

source
PathCompleteCertificates.optimality_gap — Method
optimality_gap(certificate::StabilityCertificate; atol = 1e-4, max_length = nothing)

How far the rate is known to be from the joint spectral radius: 0 when is_jsr_exact holds, otherwise the rate minus jsr_lower_bound.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem::StabilityProblem; optimizer,
                   rate = 1, check_path_complete = true, conditioning_bound = Inf)

Build, without solving, the SetProg model of the feasibility problem V_b(A_w x) <= rate^(p |w|) * V_a(x) for every edge (a, b, w), with p the template's degree and |w| the length of the word; its set variables are expanded when it is optimized.

source

Safety

PathCompleteCertificates.SafetyCertificate — Type
SafetyCertificate

A path-complete barrier function, its margin of separation between the initial and unsafe sets (positive when safety is certified), and the S-procedure multipliers initial_multipliers and unsafe_multipliers, one per node. Polyhedral certificates need no S-procedure multipliers; their entries are nothing. Their margin is measured in support/gauge or support/radius units, depending on the representation selected by SetProg.

source
PathCompleteCertificates.SafetyProblem — Type
SafetyProblem(system, S0, Su)

Safety problem for an input-free switched linear system (Anand et al., 2024), with initial and unsafe sets {x : [x; 1]' S [x; 1] ≥ 0} for S = S0, Su. For a quadratic family, the barrier at node a is [x; 1]' P_a [x; 1] with P_a symmetric, not necessarily positive semidefinite. Polynomial families construct affine polynomial barriers of the requested degree.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer, check_path_complete = true)

Solve the barrier program and return a SafetyCertificate.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer, check_path_complete = true)

Build the barrier program with quadratic, polynomial, or polyhedral SetProg families. Quadratic and polynomial barriers use nonnegative S-procedure multipliers. Polyhedral barriers use linear and second-order cone containment certificates for an ellipsoidal initial region and an exterior-ellipsoid unsafe region.

source

Optimal control

PathCompleteCertificates.OptimalControlCertificate — Type
OptimalControlCertificate

A quadratic function V_a and a gain K_a at each node a.

  • The policy is u = K_a x, where a minimizes V_a(x); simulate runs it.
  • Its worst-case cost from x is at most min_a V_a(x), which calling the certificate at x returns.
source
PathCompleteCertificates.OptimalControlProblem — Type
OptimalControlProblem(system, Q, R)

Quadratic optimal-control problem for a switched linear system with an input (Ninite et al., 2026). The stage cost is x'Q*x + u'R*u, with Q and R symmetric positive definite.

source
PathCompleteCertificates.certify — Method
certify(template, graph, problem; optimizer, psd_margin = 1e-4)

Synthesize a state-feedback policy and an upper bound on its worst-case cost, returned as an OptimalControlCertificate. Only complete graphs and QuadraticTemplate are supported; the solver maximizes Σₐ log det Pₐ⁻¹.

source
PathCompleteCertificates.optimization_model — Method
optimization_model(template, graph, problem; optimizer, psd_margin = 1e-4)

Build, without solving, the optimal-control program in S = P⁻¹, Y = KS. Only complete graphs and QuadraticTemplate are supported.

source
PathCompleteCertificates.simulate — Method
simulate(certificate::OptimalControlCertificate, x0, modes)
simulate(certificate::OptimalControlCertificate, x0, horizon::Integer;
         rng = Random.default_rng())

Run the closed loop under the policy of certificate along modes, or along horizon modes drawn uniformly at random, and return a Trajectory. At each state x, the policy applies the gain of the node whose function is smallest at x: u = K_a x with a ∈ argmin V_a(x) (Ninite et al., 2026).
