Lift reference

A lift is an operation on a path-complete graph whose result is at least as good for every template the lift is valid for. refine applies lifts, and compare uses them to order two graphs; see Lifts.

The interface

PathCompleteCertificates.AbstractLift — Type
AbstractLift

An operation on graphs: lift(L, G) is path-complete when G is, and no worse than G for every template closed under requirements(L), since a certificate on G gives one on L(G). Lifts are the steps of refine, and decide the order between two graphs in compare: when L(G) simulates H, G ≤_V H for the same templates.

source
PathCompleteCertificates.Lifted — Type
Lifted(graph, origins)

The lifted graph and, for each of its nodes, what it stands for in the original: one node for a copy, a set of nodes for the min and max lifts, a multiset for the sum lift, a (node, word) pair for the composition lifts.

source
PathCompleteCertificates.graph — Method
graph(lifted)

The lifted graph of a Lifted.

source
PathCompleteCertificates.is_valid — Method
is_valid(L, template, system) -> Bool

Whether $G ≤_V L(G)$ for every path-complete $G$, for template on system. True when the template is closed under requirements(L), or its dual under requirements(dual(L)) on the dual system (Debauche, 2024; Prop. 7.5).

source
PathCompleteCertificates.lift — Function
lift(L, graph) -> Lifted
lift(L, graph, edges) -> Lifted
lift(L, graph, node) -> Lifted

Apply L to the whole graph, at each of the given edges, or at a node. A lift applied at edges is applied at every edge when none are given; the splits are also applied at a node. A lift without the form asked for throws a MethodError.

source
PathCompleteCertificates.origins — Method
origins(lifted)

What each node of a Lifted graph stands for in the original graph.

source
PathCompleteCertificates.requirements — Method
requirements(L) -> Tuple

The Operations a template must be closed under for L to be valid on it; none for a lift that copies node functions or chains edge inequalities.

source
PathCompleteCertificates.simulation — Method
simulation(L, G, H; optimizer = nothing)

The simulation of H by lift(L, G), or nothing when there is none; it proves G ≤_V H for every template closed under requirements(L) (Philippe and Jungers, 2019; Thm. 3.5), (Debauche, 2024; Thms. 7.18, 7.55, 7.56, 7.65 and 7.66). optimizer is used by SumLift() only.

Splits

PathCompleteCertificates.OutSplitLift — Type
OutSplitLift()

Split a node into copies that each receive every incoming edge and own part of its outgoing edges, one copy per given edge.

  • lift(OutSplitLift(), graph, node) refines the forward lift of (Ninite and Jungers, 2026; Def. 3), which makes one copy per out-neighbour: one copy of node per outgoing edge, owning that edge, and node replaced by its copies; a self-loop leaves the copy that owns it for every copy. On common_graph it gives the dual of de_bruijn(1, M), where the forward lift leaves the graph unchanged.
  • lift(OutSplitLift(), graph, edges) is the partial P*-lift of (Athanasopoulos and Jungers, 2019; Def. 7) at each edge: one copy of its source owning that edge. A node whose outgoing edges are all given is replaced by its copies, so the lift at a node is the lift at its outgoing edges; otherwise a given self-loop goes from its copy to the node.

Copies are numbered last. No requirement: each copy takes the function of the node it came from.

source
PathCompleteCertificates.InSplitLift — Type
InSplitLift()

The dual of OutSplitLift: copies of a node that each leave by every outgoing edge and own part of its incoming edges. At a node it refines the backward lift of (Ninite and Jungers, 2026), one copy per incoming edge rather than per in-neighbour; at each given edge, the partial P-lift of (Athanasopoulos and Jungers, 2019; Def. 6), one copy of its destination.

source
PathCompleteCertificates.PathDependentLift — Type
PathDependentLift(M)

The M-path-dependent lift of (Philippe et al., 2016; Def. 3): InSplitLift at every edge, M times. Its nodes are the paths of length M, and origins records the last node of each. From the one-node graph it is de_bruijn(M, n_modes) up to the numbering of the nodes.

source

Products

PathCompleteCertificates.ForwardProductLift — Type
ForwardProductLift()

Replace each given edge (a, b, w) by the edges (a, b′, w·u) for every edge (b, b′, u), in a WordGraph on the same nodes: the partial T-lift of (Athanasopoulos and Jungers, 2019; Def. 4). Throws when b has no outgoing edge. No requirement: two chained edge inequalities imply the product's.

source
PathCompleteCertificates.BackwardProductLift — Type
BackwardProductLift()

Replace each given edge (a, b, w) by the edges (a′, b, u·w) for every edge (a′, a, u): the partial T*-lift of (Athanasopoulos and Jungers, 2019; Def. 5), the dual of ForwardProductLift.

source
PathCompleteCertificates.ProductLift — Type
ProductLift(T)

The T-product lift of (Philippe et al., 2016; Def. 2): the same nodes, and one edge per path of length T labelled by its word, as a WordGraph. Its own dual.

source

Combinations

PathCompleteCertificates.MinLift — Type
MinLift()

Nodes are the nonempty subsets, with an i-edge from A to B when every node of A has an i-edge into B. Requires Minimum, except for linear copositive norms on positive systems (Debauche, 2024; Thm. 7.43). A map from the nodes of H into these subsets that keeps every edge is a simulation relation between H and G, so simulation(MinLift(), G, H) returns the greatest one without building the lift. Whether one exists decides the order for every template closed under minimum (Debauche, 2024; Thm. 8.1).

source
PathCompleteCertificates.MaxLift — Type
MaxLift()

The dual of MinLift (Debauche, 2024; Lemma 7.45): nodes are the nonempty subsets, with an i-edge from A to B when every node of B is reached by an i-edge from A. Requires Maximum. Its simulation is the relation on the dual graphs, and decides the order for every template closed under maximum (Debauche, 2024; Thm. 8.5).

source
PathCompleteCertificates.SumLift — Type
SumLift(T)
SumLift()

The T-sum lift: nodes are the multisets of T nodes, with an i-edge from P to Q when the i-edges from P to Q admit a perfect matching. SumLift() stands for every T at once and is never built: simulation(SumLift(), G, H; optimizer) decides it (Debauche, 2024; Thm. 7.35 and Cor. 8.11) and returns an integer matrix C such that C·V is a certificate on H whenever V is one on G (Philippe et al., 2019; Def. IV.2 and Thm. IV.4). Requires Addition.

source

Compositions

PathCompleteCertificates.CompositionLift — Type
CompositionLift(T)

The T-forward composition lift: a node (a, j₁, …, j_T) per node a and T-tuple of modes, and for each edge (a, b, i) an edge labelled j_T from (a, j₁…j_T) to (b, i, j₁…j_{T−1}) (Debauche, 2024; Def. 7.58). Requires Composition.

source
PathCompleteCertificates.BackwardCompositionLift — Type
BackwardCompositionLift(T)

The T-backward composition lift (Debauche, 2024; Def. 7.61), the dual of CompositionLift(T). Requires InverseComposition.

source

The identity

PathCompleteCertificates.IdentityLift — Type
IdentityLift()

The lift that returns the graph; its simulation decides G ≤_V H for every template (Philippe and Jungers, 2019; Thm. 3.5).

Comparing two graphs

PathCompleteCertificates.Comparison — Type
Comparison

What compare returns: the lifts tried, the simulations found and the templates proved.

source
PathCompleteCertificates.compare — Method
compare(G, H; templates = (), system = nothing, optimizer = nothing,
        lifts = (IdentityLift(), MinLift(), MaxLift(), SumLift(),
                 CompositionLift(1), BackwardCompositionLift(1)))

Whether $G ≤_V H$, and for which of templates, as a Comparison. The lifts are tried in order, and the identity lift's simulation ends the search. The sum lift is tried only with an optimizer, and system is required when templates is nonempty. Both graphs need one mode per edge.

source
PathCompleteCertificates.lifts — Method
lifts(comparison)

The lifts compare tried, in order.

source
PathCompleteCertificates.simulations — Method
simulations(comparison)

The pairs lift => simulation, one per lift whose lifted first graph simulates the second.

source
PathCompleteCertificates.templates — Method
templates(comparison)

The given templates for which the second graph is proved no worse than the first.
